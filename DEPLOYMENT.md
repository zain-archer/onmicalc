# Deploying OmniCalc

OmniCalc is a **static site**. There is no server, database, API key or environment variable to
configure, so any static host works — including a USB stick or an `nginx` container on a laptop.

## 0. One-command paths

In a hurry? [docs/PUBLISHING.md](./docs/PUBLISHING.md) is the two-command-per-platform version of
this document.

```bash
npm run verify                       # mandatory gate: themes, typecheck, 727 tests, production build
npx serve dist                       # or: npm run preview
docker compose up -d --build         # self-hosted container → http://localhost:8080
```

CI ships with the repo: `.github/workflows/ci.yml` (Node 20 + 22), `deploy-pages.yml` (publishes
`dist/` to GitHub Pages on every push to `main`) and `release.yml` (on a `v*` tag, runs the gate and
attaches `omnica-web.zip`, `omnica-web.tar.gz` and `SHA256SUMS.txt` to a GitHub release).

## 1. Build

```bash
npm ci                 # exact dependency versions
npm run build          # tsc -b → vite build → generate sw.js + precache manifest
```

Output:

```
dist/
├── index.html
├── manifest.webmanifest
├── sw.js                # generated by scripts/build-sw.mjs
├── assets/*.js,*.css    # hashed, immutable
└── icons/*.png, favicon.svg
```

`vite.config.ts` sets `base: './'` and the app uses hash routing (`#/calculator`), so the build runs
unchanged from a sub-directory (`/omnica/`), a user site, a `file://` URL or a native WebView — no
rewrite rules are required.

Preview the production build locally:

```bash
npm run preview        # http://localhost:4173
```

## 2. Host it

### GitHub Pages

```bash
# Repository → Settings → Pages → Source: GitHub Actions
npm run build
npx gh-pages -d dist          # or upload dist/ as a Pages artifact
```

Because asset URLs are relative, no `base` change is needed for `https://user.github.io/omnica/`.

### Netlify

```
Build command:      npm run build
Publish directory:  dist
```

### Vercel

```
Framework preset:   Vite
Build command:      npm run build
Output directory:   dist
```

### Cloudflare Pages

```
Build command:      npm run build
Build output:       dist
```

### nginx

```nginx
server {
  listen 80;
  root /var/www/omnica/dist;
  index index.html;

  # Hashed assets never change → cache hard.
  location /assets/ {
    add_header Cache-Control "public, max-age=31536000, immutable";
  }

  # The service worker and HTML must always be revalidated.
  location = /sw.js     { add_header Cache-Control "no-cache"; }
  location = /index.html { add_header Cache-Control "no-cache"; }
}
```

### Apache (.htaccess)

```apache
<IfModule mod_headers.c>
  <FilesMatch "\.(js|css|png|svg|woff2)$">
    Header set Cache-Control "public, max-age=31536000, immutable"
  </FilesMatch>
  <FilesMatch "^(sw\.js|index\.html|manifest\.webmanifest)$">
    Header set Cache-Control "no-cache"
  </FilesMatch>
</IfModule>
```

### Docker (self-hosting)

```bash
docker compose up -d --build     # http://localhost:8080
# or, without compose:
npm run docker:build && npm run docker:run
```

The image is a two-stage build: Node builds `dist/`, then nginx:alpine serves it read-only with the
cache headers, gzip and security headers already configured in `docker/nginx.conf`. The container
runs with `read_only: true` plus tmpfs mounts, and has a `HEALTHCHECK` on `/`.

Push the same image to any registry (GHCR, Docker Hub, GitLab, a private registry) for Kubernetes,
Nomad, Fly.io, Railway, Render or a plain VM:

```bash
docker build -t ghcr.io/<you>/omnica:1.0.0 .
docker push ghcr.io/<you>/omnica:1.0.0
```

### S3 / any object store

```bash
npm run build
aws s3 sync dist/ s3://your-bucket/ --delete --cache-control "public,max-age=31536000,immutable"   --exclude "index.html" --exclude "sw.js" --exclude "manifest.webmanifest"
aws s3 cp dist/index.html s3://your-bucket/index.html --cache-control "no-cache"
```

### Offline from a local folder

Copy `dist/` anywhere and open `index.html`. Everything except service-worker install (which needs
`http(s)://`) works from `file://`: the calculator, all tools, history and exports.

## 3. SEO and social preview

`robots.txt`, `sitemap.xml`, Open Graph and Twitter tags ship in the build. Two optional tweaks once
you know your URL:

1. Add an absolute `<link rel="canonical" href="https://your-domain/">` in `index.html` (it is
   intentionally commented out so the default build stays host-agnostic).
2. Replace the placeholder repository URLs in `package.json`, `README.md` badges and `src/version.ts`.

## 4. Verify a deployment

1. Open the site, run `2+2` → `4`.
2. Reload with the network disabled (DevTools → Network → Offline) — the app must still load.
3. Check **About → Tools** for the full tool list and **Ctrl/Cmd+K** for the palette.
4. DevTools → Application → Service Workers: one worker, status *activated*, cache
   `omnica-<hash>`.
5. Confirm there are **zero** network requests after load (DevTools → Network, filter `Fetch/XHR`).
6. Import a reference variable: `Application → Local Storage` should only contain keys prefixed with
   `omnica.`.

## 5. Updating a live deployment

Ship a new build and reload the page: the service worker installs the new precache but **waits**,
so the app shows *“A new version is ready — Reload”* and the user decides when to switch. Nothing is
applied behind someone's back mid-calculation.

## 6. Desktop and mobile packaging

OmniCalc is a PWA, so “install” from the browser address bar is already a real desktop/mobile app
(browser Chrome/Edge: install icon in the URL bar; iOS Safari: Share → *Add to Home Screen*).

For a native shell with its own installer, icons and no browser chrome, see
[`docs/DESKTOP.md`](./docs/DESKTOP.md) and the ready-to-use Tauri configuration in
[`src-tauri/`](./src-tauri). The same `dist/` directory is reused, so the web build stays the single
source of truth.

## 7. Privacy guarantees to keep

- No analytics, no fonts, no CDNs, no remote calls — enforced by `src/hardening.test.ts`.
- All state stays in `localStorage` under `omnica.*` keys; users can export or erase it from
  **Settings → Data**.
- Nothing in the build process phones home: `npm run build` only reads files and writes `dist/`.
